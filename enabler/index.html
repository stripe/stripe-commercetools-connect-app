Test notes What each payment method needs before it shows up
  • Cards — nothing extra. 4242 4242 4242 4242 succeeds, 4000 0027 6000 3184 forces 3DS, 4000 0000 0000 0002 is declined. Any future expiry, any CVC.
  • Bank transfer — STRIPE_PAYMENT_FLOW=pi_first; bank transfers enabled in the Dashboard for a currency your account country supports; a cart with a customer; automatic capture and no setup_future_usage; a one-time (non subscription) cart; and dropin-embedded. On submit the confirm returns requires_action and the enabler reports it through onError: that is the success path, since Stripe.js renders no UI for the funding instructions. Optional: STRIPE_PAYMENT_BEHAVIOR_RULES with euBankTransferCountry (DE, FR, IE, NL) to pick which IBAN a EUR shopper wires to.
  • BLIK — pi_first as well, plus a PLN cart.
  • Pix / Boleto — a Brazilian account and a BRL cart. This page already sends their expiry options (pix.expires_after_seconds, boleto.expires_after_days).
  • Apple Pay — HTTPS and a verified domain, so it will not appear on a plain localhost dev server. The processor serves the association file at /applePayConfig from STRIPE_APPLE_PAY_WELL_KNOWN.
  • Subscriptions — a cart with a subscription product. The mode becomes subscription or setup, which changes the submit path; bank transfer is out of scope there by decision.
  • Multicapture / multirefund — STRIPE_ENABLE_MULTI_OPERATIONS=true, and multicapture enabled on the Stripe account.
